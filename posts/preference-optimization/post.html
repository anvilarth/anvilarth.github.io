Direct Preference Optimization (DPO) for Diffusion Models

Andrei Filatov · October 11, 2026 · ~20 min read

Chapter 1

What to teach after pretraining

In short: what is DPO?

Direct Preference Optimization (DPO) fine-tunes a generative model on pairs of outputs for the same prompt: a preferred one (the winner) and a rejected one (the loser). Instead of training a separate reward model and running RL, DPO treats the log-probability ratio between the trainable model and a frozen reference model as an implicit reward, and the DPO loss is a logistic loss on the winner–loser difference of that reward. For diffusion and flow models (Diffusion-DPO), likelihoods are replaced by denoising errors. This guide covers choosing preference pairs, FiFA filtering, β and learning rate, manifold drift, and keeping generation quality.

Pretraining teaches a model the relationship between text and images. A prompt about a cat should produce a cat; a prompt about a city at night should produce a city at night. But that still leaves plenty of choices. One lighting setup looks professional, another looks flat. One texture is convincing, another looks plastic.

We still need to bring the model to the quality we want: it should produce the appealing image on the right more often than the flash photo on the left. An ordinary prompt does not explain this difference to the model: it fits both images. We need another training stage where we explicitly specify which results we prefer.

This is the task of preference optimization: teach the model to draw the cat with soft natural light more often than with harsh flash, spell text on signs correctly, include every object in the prompt, or draw hands without extra fingers.

We can provide this signal in two ways: choose the better result from a pair, or assign each result a numerical score. That choice determines how we train the model.

What is DPO? Learning from pairs

DPO (Direct Preference Optimization) is useful when we know which result we like but struggle to formalize that preference. We might want more pleasing light, natural skin texture, or a particular mood. How do we combine all of that into one score? Writing a metric or building a reward model that captures our taste can be difficult. What we really want is to optimize the vibe.

Choosing between two images is often easier than expressing a preference as a number: “this one looks right.” For a single prompt, we collect a pair: the selected image is the winner, and the other is the loser. DPO uses these comparisons to teach the model to favor the results we like.

RL: learning from a score

In the second approach, the generator produces an image and a reward model returns a number: how well the result meets a chosen criterion. RL (reinforcement learning) uses these scores to update the generator toward higher expected reward. The model then generates new results, and the cycle repeats.

For example, we want to fix text in images. OCR reads the text on a sign; we compare it with the prompt and obtain a score. The generator gets a specific signal: a correct sign scores higher than one with a spelling error.

Why use a probability ratio? We want to know how much more the trainable model favors an image compared with the original model. If its probability has increased, the ratio is above one and the logarithm is positive. If it has decreased, the logarithm is negative. The reference model provides a baseline for each image.

When the rewards are equal, the probability is ½. The higher the winner’s reward relative to the loser’s, the more confidently the model predicts that the winner will be chosen. This is an assumption about how preferences work, not a consequence of the pairwise label itself.

We now want the model to assign high probability to the observed choices. Minimizing the negative log of that probability over the dataset of pairs gives the DPO loss:

Inside the sigmoid is the difference between the winner and loser relative to the reference. We want the model to favor the winner more strongly. But the function only sees the difference. It does not require each step to improve the winner’s absolute quality. We will return to this limitation.

Note: flow matching

For flow matching, the prediction target changes: instead of the added noise, the model predicts the direction and speed of motion from noise to the image, or velocity. The rest stays the same: we compute prediction errors for the trainable and reference models on the winner and loser.

What to do with β

Our loss contains a parameter that multiplies the error difference before the sigmoid:

β scales the error difference between the winner and loser before the sigmoid. With a large β, even a small advantage for the winner can push the sigmoid close to one: the pair already looks confidently separated, and its training signal weakens. With a smaller β, saturation requires a larger advantage.

In practice, β is tuned together with the learning rate. If the signal from pairs fades too quickly, the model does not get enough time to learn from the data and absorb the preference. We need to give it time to learn instead of pushing the loss into saturation immediately. The balance is between how fast the model changes and how fast the chosen β weakens the signal.

Chapter 3

Which pairs are actually useful?

Training needs winners and losers. But which images should go into these pairs so that the model learns the preference we want?

FiFA: margin, prompt quality, diversity

The most frustrating case in pairwise training is a dataset full of uncertain winners. One annotator preferred the lighting, another the composition, and a third simply chose a different style. Collecting many such pairs does not necessarily remove the uncertainty.

The score difference between the winner and loser is called the preference margin. If an evaluator barely distinguishes the images, the margin is small; if it confidently favors one, the margin is large. You can see this in the cat-knight and dragon examples: both images in the low-margin pairs look acceptable, while one image in each high-margin pair clearly violates the prompt.

This is the basis of selection in FiFA. The method considers three things: how clearly the winner beats the loser, how well the prompt is written, and how diverse the prompts in the selected set are. Pairs are ranked by a combined score.

How FiFA scores pairs

A proxy reward model estimates the preference margin, an LLM assesses prompt quality, and a neighborhood-based estimate in representation space measures diversity.

In my own work, I read these three components as follows. First, it should be clear why the winner is better. Second, the prompt should let us judge the result: the word “cat” tells us little about what was expected. Third, the selected examples should cover the domains we need. If all strong pairs are portraits, we cannot automatically expect the same improvement in other scenes.

This does not mean a long prompt is always better than a short one. Detail helps when it makes the selection criterion clearer. Lots of words without a clear request do not create a useful preference signal.

My takeaway is to establish a clear signal in each pair before scaling up the dataset. More ambiguous comparisons do not necessarily mean more useful learning.

I usually collect data in several rounds: start with automatic or synthetic labels, then generate new examples with the improved model and send them to human annotators.

Human annotation is expensive primarily because of the organization it takes. You need to agree on criteria, explain them to annotators, and check consistency. If you need professional judgment, it is hard to replace a person with the average of many random votes.

So I would first select pairs where the reason for the choice is already clear. A reward model can help with this selection, leaving ambiguous cases for human review.

What if both images are good?

Suppose two bad images have a large margin, while two excellent images have a small one. Would we really choose the first pair just because it is easier to distinguish?

No: a large margin is no substitute for a good winner. We want both a strong positive example and a clear difference from the negative one. If the winner itself is poor, we have chosen a poor target for the model.

And two excellent images do not have to compete. If both work for us, we can train the model to reconstruct each one without a loser term: use them for SFT. Here we select good examples on their own merits rather than trying to find the worse image in every pair.

My starting recommendation is simpler: first get a good winner and a clearly worse loser. I would add complex rules for ambiguous pairs after that baseline works.

Can we use another model’s images?

Off-policy data is one of DPO’s convenient features. Pairs can be collected in advance; not every example has to come from the current checkpoint. We can also use pairs from different generators: a stronger model provides the winner, and a weaker one the loser.

This can provide a clear signal without a complex evaluation system. But along with quality, we transfer the generator’s character: lighting, saturation, and textures. So resemblance to the teacher model does not, by itself, prove that we learned the intended preference.

There is also a separate question about negatives. If the loser is so far from the current distribution that our model almost never produces anything similar, how useful is it to push away from it? I do not have a universal answer. My experience with a weaker and a stronger model was positive, but that does not imply that worse losers always mean better training. An external winner paired with an on-policy loser remains a separate hypothesis to test.

Chapter 4

The loss improves, the images get worse

The DPO loss asks the model to reconstruct the winner better relative to the loser. But this comparison can improve even if winner reconstruction gets worse: loser reconstruction only has to deteriorate faster. The winner’s relative advantage grows, so the DPO loss falls, even as errors on both images rise.

The plot from Diffusion-SDPO shows changes in error relative to the reference. Orange is the winner; green is the loser. Both rise: the model reconstructs both images worse. But the loser error rises faster, so the “winner − loser” difference, shown in purple, falls. For DPO, that difference is moving in the desired direction even though winner reconstruction is deteriorating.

In generated images, this might look like the model picking up the desired cinematic lighting while faces and hands become distorted. It has learned the lighting preference, but its ability to draw plausible objects has deteriorated. This is an example of manifold drift: in chasing a preference, the model loses its ability to generate images properly.

Keeping the model close to good examples

A common strategy is, in effect, to do SFT on the winner alongside DPO. I would highlight three methods that I find useful in practice: DPO + SFT, BDPO, and ThermoDPO.

BDPO: bounding the loser term

SFT directly increases the probability of a good example. Bounded-DPO, proposed for language models, puts more emphasis on learning from the winner in a different way: it limits how much the loss can decrease through loser suppression alone.

In ordinary DPO, the model can improve the winner-to-loser probability ratio by driving the loser’s probability lower and lower. BDPO replaces the loser probability with a mixture: part comes from the trainable model and part from the frozen reference. Even if the trainable model assigns the loser almost zero probability, the reference contribution remains. Further reducing the loser’s probability therefore becomes less and less useful.

ThermoDPO: anchoring to the winner

In ThermoDPO for flow models, the connection to SFT is more direct: one loss combines pairwise comparison with the ordinary task of reconstructing the winner. While the preference is not yet learned, the model learns to distinguish the winner from the loser. When the pairwise comparison provides little signal, training on the winner continues: the same task we previously added through SFT regularization.

Predicting the image itself might make quality easier to control during preference optimization. This is still a hypothesis: changing the target does not imply that manifold drift will disappear.

Chapter 6

Where I would use DPO

When to choose DPO

I would use DPO where a preference is easier to show than to express through a reward: which lighting looks professional, which composition works better, which style we want. Pairs let us convey these choices to the model even without a separate reward for them.

For a specific task, such as fixing illegible text, I would look toward RL with a reward for that task. We can evaluate whether the text is spelled correctly and train the model to improve that particular result. The constraints are the evaluator’s quality and how many rollouts we can afford.

Where to get good examples

The choice of winner largely determines the result. If we take good images from another generator, we may inherit its characteristic lighting and style along with its quality. Even the CFG used to produce the examples affects what we teach the model. When collecting pairs, we therefore need to understand which properties of the winner we actually want in our own generations.

The source of good examples also determines whether we need a separate SFT stage before DPO. If good external examples are already available, we can use them as winners and train with DPO and SFT together. If we collect pairs from our own generations, preliminary SFT can improve the material for the next round: the model will produce better winner candidates.

How to continue training

DPO can run for several rounds: start with automatic labels, then, after the model improves, collect new pairs and send them to human annotators. The next round will then use generations from the updated model.

After DPO, we can move to RL: first use pairs to establish broad visual preferences, then use a reward to address specific weaknesses.

DPO is largely about the vibe in your data. You need to know which preference you want to learn and collect pairs that actually express it. The winner should be good in its own right, and the reason for choosing it should be clear.

Then you need to learn that preference carefully: tune β together with the learning rate so that the signal from pairs does not fade too early and the model does not overfit. Adding SFT on the winner helps prevent manifold drift: it keeps the model learning from good examples while DPO teaches the preference.

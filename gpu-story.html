How GPUs Work:
From Triangles to Tensor Cores

The story of how a triangle-drawing chip became the most important chip on the planet

Andrey Filatov · 2026 · ~20 min read

I run models on GPUs every day, but for a long time I had no idea what was happening inside. This post is my attempt to figure it out from scratch: what problem gave birth to the GPU, how engineers solved it, and where we ended up.

Глава I

Как компьютер рисует картинку

Quake и боль CPU

1996 год. На экранах — Quake. Первый 3D-шутер, где камера свободно движется по трёхмерному пространству.

Разрешение скромное: 640 на 480. Но давайте посчитаем. 640 × 480 = 307 200 пикселей. Для каждого — цвет, освещение, глубина. На пиксель: 20–50 операций. На кадр: 10–15 миллионов. Кадров в секунду: 30. Итого: ~300–450 миллионов операций в секунду.

Pentium 200 МГц выдавал ~200 MIPS — уже на грани. Но это в идеальных условиях. При рендеринге каждый пиксель обращается к текстуре по непредсказуемому адресу → кэш-промах → pipeline стоит 50–100 нс → десятки потерянных тактов. На каждый пиксель.

Pentium: 200 MIPS. Quake хочет: 300+ MIPS. Кэш-промахи срезают ещё в 2–3 раза. CPU физически не успевает.

CPU спроектирован для другого. Большая часть транзисторов — управляющая логика, а не вычисления. Графика — миллионы простых одинаковых операций. Тут одно мощное ядро проигрывает.

Путь одного треугольника

Чтобы понять какие операции убивают CPU, проследим один треугольник от чисел до пикселя.

Шаг 1 — Вершины. Три точки в 3D: A(−1, 2, 3), B(2, −1, 1), C(0.5, 1, 2).

Шаг 2 — Трансформация. Умножаем на MVP 4×4 → экранные координаты. 100K треугольников = 4.8M независимых умножений.

Шаг 3 — Растеризация. Какие пиксели внутри? Каждый тест независим.

Шаг 4 — Фрагменты. Цвет каждого пикселя: свет, текстура. Одна формула, разные данные.

Шаг 5 — Framebuffer. Один треугольник готов. Осталось 99 999.

Интерактивное демо — путь одного треугольника

Формула одинаковая, данные разные, всё независимо. Идеальная задача для параллелизма.

DirectX и OpenGL: попытка решить софтом

Ещё проблема: каждая видеокарта — свой язык. Разработчик писал отдельный код для каждого чипа.

Совместимость решена. Скорость — нет. Нужно специализированное железо.

Глава II

Проектируем GPU с нуля

Графика — миллионы одинаковых независимых операций. CPU тратит транзисторы на управление. Давайте спроектируем процессор для нашей задачи.

Шаг 1: Множим ALU

Берём CPU, убираем «умное», оставляем ALU. Он проще → можно уместить много.

~80% площади CPU — управление. GPU выкидывает управление, множит вычислительные блоки.

Шаг 2: SIMD — все делают одно и то же

Все ALU выполняют одну инструкцию, но с разными данными. SIMD — Single Instruction, Multiple Data.

В современных GPU это реализовано через warps — группы из 32 потоков, исполняющих одну инструкцию синхронно. Один warp на 32 ALU. Все получают одну команду «умножь» и одновременно умножают 32 разных числа.

Warp divergence: при ветвлении часть потоков простаивает. Чем меньше ветвлений — тем эффективнее GPU.

Для графики это работает: все фрагменты обрабатываются почти одинаково — одна формула освещения, мало ветвлений. Потери от divergence минимальны.

Шаг 3: Latency hiding — прячем задержки

Память медленнее процессора. Запрос текстуры → 200–400 тактов ожидания. Все 32 ALU в warp простаивают.

Решение: GPU держит в регистрах состояние не одного warp, а десятков. Переключение мгновенное — за один такт. Пока warp A ждёт данные, GPU считает на warp B. Потом C. Потом D. К моменту, когда данные для A приходят — очередь до него как раз дошла.

CPU прячет задержку кэшами. GPU прячет задержку переключением потоков. Два подхода к одной проблеме.

Результат: GeForce 256

Массив простых ALU + SIMD + переключение warps = первый GPU.

1999: NVIDIA GeForce 256. 17 миллионов транзисторов, 120 МГц, 10 миллионов полигонов/сек. Аппаратный Transform & Lighting — трансформации переехали с CPU на видеокарту.

Глава III

От шейдеров к CUDA

Шейдеры: GPU учится импровизировать

Начало 2000-х. Fixed-function pipeline: каждая функция зашита в кремний. Хочешь реалистичную воду? В pipeline нет такой функции. Ждать новый чип — годы.

В 2002 году DirectX 9 принёс Shader Model 2.0 — и всё изменилось. Шейдеры — маленькие программы, которые пишет разработчик, а GPU исполняет для каждого фрагмента или вершины. Vertex shader двигает вершины (волны). Fragment shader считает цвет (отражения).

GPU из «калькулятора с кнопками» превратился в «программируемый калькулятор».

Каждый параметр — переменная в шейдере. GPU считает для ~50 000 фрагментов параллельно, 60 fps.

Проблема: раздельные блоки

Шейдерные блоки были физически разделены: одни для вершин, другие для пикселей. Тяжёлая геометрия — пиксельные простаивают. Сложные материалы — вершинные простаивают.

Раздельные vs унифицированные блоки

50% геометрия

Двигай ползунок: при перекосе нагрузки раздельные блоки простаивают, унифицированные — нет.

Unified → CUDA

В 2006 году NVIDIA сделала все блоки одинаковыми — unified shader architecture (GeForce 8800). GPU сам распределяет нагрузку. И тут инженеры поняли: если ядра универсальные — зачем ограничиваться графикой?

Ian Buck из Стэнфорда, при поддержке DARPA, создал Brook — первый язык для GPGPU. NVIDIA наняла его в 2004, и в феврале 2007 вышла CUDA: нормальный C-код → компилируй → запускай на тысячах ядер GPU.

CUDA создавалась не для AI. Это инструмент для параллельных вычислений — любых.

Глава IV

От вычислителя к AI-чипу

После CUDA у GPU было всё для вычислений — тысячи ядер, SIMD, latency hiding. Но учёные и инженеры сразу нашли слабые места. Каждое поколение архитектуры — это ответ на конкретную проблему, которую обнаружили пользователи предыдущего.

Fermi → Maxwell: GPU взрослеет (2010–2014)

Проблема: учёные запустили физическую симуляцию на GPU — результат отличался от CPU. Почему? Нет защиты от случайных ошибок в памяти (bit flips). Один перевёрнутый бит — и расчёт неверный. Для игр — незаметно. Для науки — катастрофа.

Fermi (2010): ECC-память (защита от ошибок) + полноценные кэши L1/L2. GPU стал надёжным для серьёзных вычислений.

Проблема: чтобы запустить новые вычислительные потоки, GPU обращался к CPU. Каждый раз. Это бутылочное горлышко — CPU не успевает кормить GPU задачами.

Kepler (2012): Dynamic Parallelism — GPU сам порождает новые потоки из своих результатов, не обращаясь к CPU.

Maxwell (2014): Фокус на энергоэффективность — больше производительности на ватт. GPU перестал быть пожирателем энергии.

Три поколения — три конкретных проблемы. Каждое решение открывало новые задачи для GPU.

Pascal (2016): одного GPU мало

Проблема: модели и данные росли быстрее памяти. Один чип — 12–16 ГБ. А нужно больше. GPU можно поставить рядом два, но связь через PCIe — тонкая трубка: ~16 ГБ/с. Данные между GPU текут как через соломинку.

Volta (2017): AI в кремнии

Проблема: ML — это матричные умножения, миллионы раз. Обычное CUDA-ядро делает одну операцию (a×b+c) за такт. Для матрицы 4×4 — 64 такта. Расточительно.

Tensor Cores — новый тип блока в кремнии. Вся матрица 4×4 за один такт. Не софт — физические транзисторы. Tesla V100 стал стандартом data-центров.

Hopper (2022): эра трансформеров

Проблема: LLM — GPT, LLaMA — работают с разной точностью на разных слоях. FP16 везде — расточительно: многие слои не нуждаются в высокой точности, но занимают столько же памяти и bandwidth.

Transformer Engine — аппаратный блок, динамически переключающий FP8↔FP16. Плюс HBM3 (80 ГБ, 3.35 ТБ/с), NVLink 4.0 (900 ГБ/с). H100 стал стандартом индустрии.

Что дальше: стена энергии, стена памяти, чиплеты

Каждое следующее поколение GPU упирается в новые ограничения:

Energy wall. Blackwell (2024) — 700W на чип. Дата-центр из тысяч GPU потребляет как небольшой город. Наращивать мощность бесконечно нельзя — охлаждение, электроснабжение, стоимость. Производительность на ватт важнее абсолютной производительности.

Память как bottleneck. Вычислительная мощность GPU растёт быстрее, чем пропускная способность памяти. Разрыв увеличивается каждое поколение — GPU всё чаще простаивает в ожидании данных. Это проблема inference, но и training упирается в memory bandwidth при больших batch size.

Chiplets. Кремниевые пластины не бесконечны — один монолитный чип не может расти вечно (дефекты, yield). Решение: чиплеты — несколько маленьких кристаллов на одной подложке, соединённых быстрыми интерконнектами. AMD уже делает это в CPU (Ryzen), NVIDIA двигается в этом направлении с Blackwell (два кристалла GB202).

Каждое поколение GPU — ответ на конкретную проблему предыдущего. Спираль продолжается.

Глава V

Полный круг

Спираль специализации

Начинали со специализации: GPU — штука для треугольников. Фиксированные функции, жёсткий pipeline.

Потом — универсализация. Шейдеры, CUDA, GPGPU. Можно считать что угодно.

И снова специализация — но на новом уровне. Tensor Cores — «фиксированные функции» для матриц. Transformer Engine — блок под конкретную архитектуру нейросетей.

Технологии развиваются по спирали. Каждый виток — на более высоком уровне абстракции. GPU прошёл этот цикл за 25 лет.

Проблема: memory-bound inference

Спираль не остановилась. Новая волна специализации рождается из конкретной проблемы.

Когда LLM генерирует текст — один токен за раз. На каждый токен модель читает все свои веса из памяти: миллиарды параметров. Вычислений на прочитанный байт — крошечное количество. Arithmetic intensity (отношение вычислений к данным) ≈ 1 FLOP/byte. Для полной утилизации H100 нужно ~300 FLOP/byte.

Результат: тысячи ядер и Tensor Cores простаивают, ожидая данные из HBM. Вычислительная мощь H100 используется на 5–15%. KV-cache растёт с длиной контекста, съедая гигабайты.

Решения: TPU, Groq, Cerebras

Эта проблема породила новые чипы — каждый со своим подходом:

Google TPU — systolic array: данные текут через решётку вычислительных элементов без обращения к глобальной памяти. Ставка на масштаб.

Groq LPU — убрал HBM. Вся модель в SRAM — быстрой on-chip памяти. Нет бутылочного горлышка, детерминистическая архитектура.

Cerebras WSE — один чип размером с кремниевую пластину. 44 ГБ SRAM, 850 000 ядер. Данные и вычисления на одном кристалле.

Каждый чип — новый виток спирали. GPU был универсальным, но для inference LLM оказался неоптимальным — и появились чипы под конкретную задачу.

Мост к следующему посту

Теперь у тебя есть ментальная модель GPU. Почему параллельный — потому что графика такая. Почему SIMD — формулы одинаковые. Почему Tensor Cores — ML это матрицы. Почему альтернативы — inference это не те же вычисления, что training.

Но знать архитектуру — половина дела. Настоящая магия — когда пишешь код, который её учитывает. Warp size, occupancy, bank conflicts, эффективные kernels.
